## 2024-05-14 - Add missing disabled/busy state styles to `.btn` components
**Learning:** The existing `.btn` component classes (e.g. `btn-primary`, `btn-ghost`) lacked explicit visual states for `:disabled` and `[aria-busy="true"]`, despite JavaScript correctly applying these attributes during asynchronous operations (like form submissions). This creates a jarring UX where the user can't visually distinguish an active submitting state from a normal idle state, especially since hover styles were still applying.
**Action:** Always ensure that core interactive components (like buttons) have exhaustive state definitions (`:hover`, `:active`, `:focus-visible`, `:disabled`, `[aria-busy="true"]`) in the CSS. When JavaScript updates ARIA attributes to reflect state, the CSS must respond accordingly.
